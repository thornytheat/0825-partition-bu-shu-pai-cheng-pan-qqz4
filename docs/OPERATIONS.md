# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可整批签发；对仍有差异的版本可填写暂缓意见。
5. 存在冲突行时不必整批等待：在工作台选中无争议、判定 READY 的分组单独签发，争议分组保持暂缓。
6. 同一记录号指向不同分组时，相关分组同时暂缓，直到补证裁决完成。
7. 在争议面板按来源同列填写补证行并提交，系统对受影响的原分组与改归目标分组整体复算；任一组未通过，两组都不能签发。
8. 同一争议只采信一个补证版本，并发提交的落败版本被拒绝且不会覆盖胜出版本；已签发分组不接受任何后续补证改写。
9. 导出复核证据并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
